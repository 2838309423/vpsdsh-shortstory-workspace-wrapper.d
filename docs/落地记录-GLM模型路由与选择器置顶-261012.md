## 2. 选择器顺序是客户端**硬编码**的（关键发现）

`<dsh 安装目录>/node_modules/@deepseek-ai/dsh-client-ui-model-selection/lib/client.js`：

```js
function orderModelProviders(groups) {
  return groups.toSorted((left, right) =>
    (left.id === "deepseek-account" ? 0 : left.id === "deepseek-official" ? 1 : 2) -
    (right.id === "deepseek-account" ? 0 : right.id === "deepseek-official" ? 1 : 2));
}
```

- `deepseek-account` / `deepseek-official` 固定 0/1，**其余提供商一律 2** ⇒ 不补丁的话 GLM 只能排在 DeepSeek 后面，
  配多少 profile 都没用。
- 该函数被选择器菜单与命令面板（`optionsOf`）共用 ⇒ 补一处两处都生效。
- 组内模型顺序另由 `rankByName(group.models, 空查询)` 决定，空查询时**保持 Host 目录顺序**
  ⇒ 组内要让 flash 排第一，靠的是 `llm-pi-ai` 的 `models` 列表顺序（见下）。

## 3. 改动（三步，全部幂等/可回滚）

### ① 凭据：`refs.GLM_API_KEY`（不进仓）

密钥取甲方 `.bashrc` 里 GLM 态的那把（`open.bigmodel.cn` 智谱 key，与 claude 侧 8199 微代理同源），
用 GUI 同款 RPC 写入托管凭据档，**不打印、不入库**：

```bash
curl -s -b /tmp/dsh.jar -X POST http://127.0.0.1:19387/api/credentials/set \
  -H 'content-type: application/json' --data-binary @/tmp/rpc-cred.json   # args={ref:"GLM_API_KEY",value:"…"}
```

读数：`credentials/describe` ⇒ `GLM_API_KEY: {configured: true, source: "file"}`。
落点：`$DSH_HOME/.credentials.yaml`（600）。

### ② 路由：profile 的 `llm-pi-ai` 段

写进 `profile/cordis.patch.yml`（权威副本；落地到 `$DSH_HOME/profiles/vps/cordis.patch.yml`）：

```yaml
- id: llm-pi-ai
  name: "@deepseek-ai/dsh-llm-pi-ai"
  config:
    providers:
      zai-coding-cn:            # pi-ai 目录档：baseURL=https://open.bigmodel.cn/api/coding/paas/v4（OpenAI 兼容）
        apiKeyEnv: GLM_API_KEY
        displayName: 智谱 GLM
        models:
          - id: glm-5.3-flash   # 只列 flash：不写就会把智谱目录 7 个模型全塞进选择器，flash 反而排在中间
```

现场是**用设置 RPC 写活的**（`settings/mutate`，`applies: live` ⇒ 立即生效，不用重启 web）：

```bash
curl -s -b /tmp/dsh.jar -X POST http://127.0.0.1:19387/api/settings/mutate -H 'content-type: application/json' \
  --data-binary @/tmp/rpc-mutate.json   # args={ns:"llm-pi-ai",expectedRevision:0,
                                        #       ops:[{op:"set",path:["providers","zai-coding-cn"],value:{…}}]}
```

### ③ 顺序：客户端补丁 + 幂等脚本

新增 `bin/patch-model-order.sh {check|apply|revert}`：把上面那个三元表达式改成
`zai-coding-cn → 0`、`deepseek-account → 1`、`deepseek-official → 2`、其余 `3`，并同步改那段 JSDoc 注释。
首次 `apply` 会在同目录留 `client.js.orig-dsh` 原档，`revert` 从它还原。

```bash
bash bin/patch-model-order.sh check    # __PATCH__ pristine|applied
bash bin/patch-model-order.sh apply    # 幂等
bash bin/patch-model-order.sh revert   # 回滚（会退回 DeepSeek 在前）
```

## 5. 未做 / 风险 / 回滚

- **未做**：没有把 GLM 设成新会话默认模型（甲方只是要「好选」，默认仍是 `deepseek-official/deepseek-flash`）。
- **风险 1**：`apply-profile.sh` 会用仓库副本覆盖落地 patch ⇒ 仓库副本已同步写上 `llm-pi-ai` 段
  （两者 `yaml.load` 后 **data 完全相同**，已校验），以后跑 apply 不会把 GLM 弄丢。
- **风险 2**：`npm i` / 升级 `@deepseek-ai/dsh` 会把 `client.js` 覆盖回原样 ⇒ 顺序退回 DeepSeek 在前，
  重跑 `bash bin/patch-model-order.sh apply` 即可（`check` 会报 `pristine`）。
- **风险 3**：这条路由烧的是甲方自己的智谱配额（与 claude 同一把 key、同一账号），
  只是「多了一个可选项」，不选它就不花钱；回滚＝删 `llm-pi-ai` 段（或 `revert` 客户端补丁）。
- **回滚**：`bash bin/patch-model-order.sh revert` + 设置页删掉 `zai-coding-cn`（或把仓库 patch 段的
  `llm-pi-ai` 整段删掉后 `bash bin/apply-profile.sh` 再 `bash bin/web.sh restart`）。
