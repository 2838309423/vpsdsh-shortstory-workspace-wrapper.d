## §0 一句话结论（含甲方最关心的问题）

**系统盘准备 = 一次性动作；做完后「保存镜像」就永久跳过环境准备环节，每支新片子只需推 `.blend` + 跑一条渲染命令。**

直接回答「下次做类似内容能不能跳过本次的环境准备」：

> **能，但必须走「保存镜像」这一步——只把实例关着（关机保留）不够稳。**
> - 关机保留：容器实例**连续关机 15 天自动释放**（数据全清），且**关机不预留 GPU**，下次开机可能"无空闲卡"。
> - 保存镜像（推荐）：镜像存在你的账号里（默认 20 个配额，**30 GB 以内免费**），下次**从镜像开新实例**，开机即是有 Blender + ffmpeg 的机器，换地区/换卡型也能用。**AutoDL 不支持导入外部镜像**，所以环境必须在实例里建一次再存。
> - 下次仍要重做的只有三件事（几分钟）：推本次 job 的 `.blend`/spec → 带卡验证（可选）→ 渲完 rsync 回 usavps。

## §2 目标定义（DoD：「系统盘配置完成」= 什么）

镜像里（= 系统盘 `/` 上）必须同时满足，且可机检：

1. **系统库齐**：`ldd <blender 真身> | grep 'not found'` 为空（X/GL/SM/ICE 等；Blender 自带 `lib/` 里已捆绑 24 个内部库）。
2. **Blender 4.5.14 LTS** 在位：`blender --version` 首行含 `4.5.14`；装 `/opt/blender-4.5.14-linux-x64`，`/usr/local/bin/blender` 是**包装脚本**（见 §5 坑 1）。
3. **ffmpeg** 在 PATH（就地封 mp4 用）。
4. **环境件**在系统盘：`/root/vibe-render/{bootstrap.sh,selftest.sh,smoke_cpu.py,render_job.py,run-job.sh,README.md}`。
5. **selftest 全绿**：`bash /root/vibe-render/selftest.sh` 末行 `__SELFTEST__ <n> 0`，其中含**一次真跑的 Cycles CPU 出图**（无卡模式也能跑）。
6. **帧序列/产物落点**在数据盘 `/root/autodl-tmp/jobs/...`（**不进镜像**）。
7. 控制台里出现自定义镜像（建议命名 `blender-4.5.14-cuda-ready-v1`），容量 ≤30 GB（免费额度内）。

## §3 施工步骤（Phase 0 → 4）

### Phase 0　控制台建实例（甲方，约 5 分钟，现金 ≈ ¥0.01）

1. 注册/实名 → 充值 **¥10**（微信/支付宝）。
2. **镜像选最小基础镜像**（如「Miniconda3 / conda3（ubuntu22.04）」）；**别选 PyTorch/TensorFlow 全家桶**——那 20 GB CUDA 框架对本用途毫无用处，还会把你要保存的镜像撑大。AutoDL 的 NVIDIA 驱动由宿主挂载，**任何镜像都能用 CUDA**。
3. 卡型：优先 **4090**（此前核到 ≈¥1.98/h，3090 ≈¥1.20/h；**以网站现价为准**）；计费方式选**按量计费**（不要包日/包周）。
4. 开机 → 立刻在控制台**关机**（几秒钟，≈¥0.01）→ 再点**无卡模式开机**（实例必须先存在才能无卡开机）。
5. **顺手做两件事**（都只做一次）：
   - 控制台「设置 → SSH 公钥」→ 粘贴 usavps 的公钥全文（usavps 上 `cat ~/.ssh/id_ed25519.pub` 即可取；**私钥不出 usavps**）。
   - 首页开启「实例到期/释放预警」。
6. 把这两样告诉接续会话：**SSH 登录指令（`ssh -p <端口> root@connect.<区域>.seetacloud.com`）**；公钥是否已注册成功。

### Phase 1　无卡模式里装环境（¥0.1/h，预计 15–40 分钟）

在 usavps 上一条命令（环境件 + Blender 官方 tar.xz 一起推过去，随后实例内引导 + 自检）：

```bash
cd /home/longxia/vpsdsh-shortstory-workspace-wrapper.d
bash tools/autodl/push-payload.sh \
  --host connect.<区域>.seetacloud.com --port <端口> \
  --with-blender \
  --blender-tar /home/longxia/media-shared/_dl/blender-4.5.14-linux-x64.tar.xz
```

（`--dry-run` 可先空跑看目标机信息；`--skip-selftest` 跳过自检；不带 `--with-blender` 则让实例自己从
`download.blender.org` 下载——**国内到国际带宽不稳，推荐推过去**。tar.xz 378,045,212 B，
sha256 `9ba871ff2ecd36526b77432745980b7e6664ecd0c7ca11c48849073dcfe06da3`）

实例内等价的手工步骤（若你想在实例里敲）：

```bash
mkdir -p /root/_dl /root/vibe-render                       # 环境件解到系统盘（要进镜像）
tar -xzf /root/_dl/autodl-payload.tar.gz -C /root/vibe-render
bash /root/vibe-render/bootstrap.sh --tarball /root/_dl/blender-4.5.14-linux-x64.tar.xz
bash /root/vibe-render/selftest.sh                          # 无卡模式也能跑（纯 CPU）
```

预期末行：`__SELFTEST__ <n> 0`。
无卡模式里 `nvidia-smi` 报错是**正常的**（0.5 核/2 GB/无卡），selftest 不把它算失败。

### Phase 2　固化：保存镜像（≈2 分钟，¥0）

1. 控制台**关机**（保存镜像必须先关机）。
2. 「更多操作 → 保存镜像」→ 命名 `blender-4.5.14-cuda-ready-v1`。
3. 核对：镜像菜单里能看到；容量（基础镜像 + Blender 1.1 GB + 系统库 ≈ 6–12 GB）在 30 GB 免费额度内。
4. 保存前确认**没有把帧序列写在系统盘**（§1 勘误）。

### Phase 3　带卡验证（¥2 以内；这一步只有带卡能验）

```bash
# 正常开机（带卡）后，在 usavps 上：
ssh -p <端口> root@connect.<区域>.seetacloud.com 'nvidia-smi; bash /root/vibe-render/selftest.sh'
# 真渲一帧（换成真实 job 的 .blend），拿到本机 spf（秒/帧）：
ssh -p <端口> root@connect.<区域>.seetacloud.com \
  'nohup bash /root/vibe-render/run-job.sh \
      --blend /root/autodl-tmp/jobs/smoke/scene.blend \
      --out   /root/autodl-tmp/jobs/smoke/frames \
      --res 1080x1920 --samples 24 --device CUDA \
      --encode /root/autodl-tmp/jobs/smoke/smoke.mp4 \
      > /root/autodl-tmp/jobs/smoke/nohup.log 2>&1 &'
```

- 断言口径：日志末行 `__RENDER__ ok=1 ... spf=<秒/帧>`；若出现 `error=gpu_not_available`（退出码 4），说明卡没挂上/镜像里缺 `libcuda.so.1` ⇒ 回无卡模式补，再重存镜像。
- **务必显式 `--device CUDA`**：不显式指定时 Cycles 默认 CPU —— 那就是花卡的钱跑 CPU。
- `--shutdown` 收尾 ⇒ 渲完自动关机，按秒计费停止。

### Phase 4　收尾

```bash
rsync -az --partial -e "ssh -p <端口>" root@connect.<区域>.seetacloud.com:/root/autodl-tmp/jobs/<job>/ /home/longxia/media-shared/autodl-out/<job>/
```
把 `render_report.json` 里的 spf 填进 §9 读数表 ⇒ 以后估时长/成本就有一手数字。

## §5 坑与硬口径（都实测过；写脚本必守）

1. **`blender` 只能用包装脚本，不能用软链**（本轮实测踩到）：Blender 官方 tar.xz 靠 `$ORIGIN/lib` 找自己捆绑的 ~24 个库，
   `ln -s /opt/blender-.../blender /usr/local/bin/blender` 会让 `$ORIGIN` 变成 `/usr/local/bin` ⇒ 全部 `not found`。
   `bootstrap.sh` 已改成写包装脚本（必要时带 `LD_LIBRARY_PATH`），**别手工改回软链**；
   更要命的是"目标还是软链时用 `>` 写包装脚本"会**顺链砸掉真身**（§9.1 缺陷 2），写之前必须 `rm -f`。
2. **帧序列一律写 `/root/autodl-tmp`**（免费 50 GB 数据盘，**不进镜像**）；写系统盘会污染要保存的镜像。
3. **保存镜像前必须先关机**；只存**系统盘**；AutoDL **不支持导入外部镜像**。
4. **无卡模式只有 0.5 核 / 2 GB**：`apt-get update+install` 与 xz 解包会慢（预计 10–25 分钟），**不是卡死**。
5. **无卡模式会释放 GPU**：之后正常开机若没空闲卡 ⇒ 等待、或从镜像**另开实例**、或「迁移实例(同地区)」克隆。
6. **连续关机 15 天释放实例**（数据全清）⇒ 别把唯一副本放在实例里。
7. **`--device CUDA` 必须显式**；`render_job.py` 找不到卡会以退出码 4 **硬失败**，不静默退 CPU。
8. **`--python-exit-code 1` 必带**：否则脚本抛异常 Blender 也退 0，会把"静默失败"当成功。
9. **版本对齐 4.5.14 LTS**：usavps/客机侧就是 4.5.14；用更高版本存盘的 `.blend` 回开会有兼容告警。
10. **长渲染别裸跑 SSH**：用 `nohup ... &` 或 `tmux`；`--shutdown` 是收尾自动关机的最省事写法。
11. **中文字幕/文字需要字体**：`bootstrap.sh --cjk` 会 apt 装 `fonts-noto-cjk`（一次性，进镜像）；也可把字体文件放进 job 目录。
12. **`/root/autodl-tmp` 在「重置系统/更换镜像」时不受影响**，所以临时产物放那里最安全。

## §7 风险与回退

| 风险 | 触发 | 对策 |
|---|---|---|
| 抢不到卡 | 无卡模式释放了 GPU，别人租走 | 保存镜像 → 从镜像另开实例 / 迁移实例(同地区) / 换区域 |

| 镜像超免费额度 | 基础镜像选太大 / 帧序列写进系统盘 | 选最小基础镜像；帧序列写数据盘 |

| 保存镜像后才发现缺库 | 无卡模式验不出 CUDA | 先保存镜像 → 带卡验证 → 缺啥回无卡补 → **重存新镜像**（旧镜像删掉省额度） |

### §9.1 本轮预验证发现并修掉的缺陷（都是在 usavps 上先跑才暴露的）

1. **软链 vs 包装脚本**：`ln -s <真身> /usr/local/bin/blender` 会让 Blender 的 `$ORIGIN/lib` 失效 ⇒ 24 个自带库全
   `not found`。改为**包装脚本** `exec "<真身绝对路径>" "$@"`。
2. **写包装脚本时砸掉真身**（严重）：`~/bin/blender` 还是上一轮的**软链**时，`> $BINDIR/blender` 会**顺着软链**
   把 156 MB 的 Blender 真身覆盖成 181 B 的脚本 ⇒ 包装脚本 exec 自己 ⇒ **无限 exec 循环把机器挂住**。
   修法：写临时文件 + `rm -f` 目标 + `mv` 落位（永不穿过软链写）；并在 bootstrap/selftest 里加"真身尺寸 > 1 MB"断言。
3. **假绿断言**：版本断言原来是"行内含 `4.5.14`"，而报错信息里的**路径**也含 `4.5.14` ⇒ 坏掉的安装被判 OK。
   改为必须**以 `Blender 4.5.14` 开头**。
