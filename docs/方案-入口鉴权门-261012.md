# 入口鉴权门（`bin/web-gate.py`）—— 2026-10-12 落地

- 目标机：`usavps`（Tailscale `100.85.190.17`），服务目录 `/home/longxia/vpsdsh-shortstory-workspace-wrapper.d`
- 甲方口径（原话要点）：两台手机都登 Tailscale；**方案①「tailscale 登录时永久访问」**、
  **方案②「即使 tailscale 登录还要在 web 里输密码，用户名 longxia / shortstory，root 不给 web 登录，
  口令与实际 Linux 账户一致」**。
- 一句话结论：原 `bin/ts-proxy.py`（纯 TCP 转发）升级为 **`bin/web-gate.py`**：同一个 Tailscale 监听、
  同一套直通语义，多出 **off / tailnet / password** 三档进门方式，**切档不用重启**。
  现在书签统一是 **`http://100.85.190.17:19387/`**，令牌轮换不再影响它。

## 一、现在怎么用（三行就够）

| 事 | 命令 |
|---|---|
| 上课/看书签 | `http://100.85.190.17:19387/`（Tailscale 网内，两种模式同一个书签） |
| 切档 | `cd /home/longxia/vpsdsh-shortstory-workspace-wrapper.d && bash bin/web.sh gate tailnet`（或 `password` / `off`） |
| 看档 | `bash bin/web.sh gate status`（`bash bin/web.sh status` 里也带一行） |

> 切档不重启：门(web-gate)**每条连接现读** `state/gate.conf`，2 秒内自动跟上。

## 二、三档语义

| 档 | 谁能进 | 观感 |
|---|---|---|
| `off` | 与老 ts-proxy 完全一致：只有拿到 `?token=<当前令牌>` 并换到 cookie 的设备能进 | 回滚档，令牌一换书签就 401 |
| `tailnet`（**当前生效**，方案①） | Tailscale 网内**任何**登录设备，直开干净 URL 即进 | 门发现 DSH 回 401（没 cookie）就自动补一次 `/?token=<当前令牌>` 跳转 ⇒ **永久书签**，重启也不怕 |
| `password`（方案②） | Tailscale 网内 **且** 在登录页用 **longxia / shortstory 的真实 Linux 口令**通过 | 打开干净 URL 先出登录页；通过后发 365 天 HMAC 签名 cookie，之后同① |

三种档都**只在 Tailscale 网卡上监听**，公网 IP 上零监听（`ss -ltn | grep 19387` 只有 `127.0.0.1` 与 `100.85.190.17`）。

## 三、口令怎么校验（无 root 权限，用系统自己的 PAM）

本机 `longxia` 无 sudo 免密、读不到 `/etc/shadow`，`sshd` 也是 `PasswordAuthentication no`（不能用 SSH 试口令）。
实测可行的两条路（都走 setuid 程序 → PAM）：

| 账号 | 校验方式 | 实测 |
|---|---|---|
| `longxia` | `sudo -S -k -u root /bin/true`（sudo 校验的是**发起者 longxia** 的口令） | 错口令 ⇒ `1 incorrect password attempt`，EXIT=1 |
| `shortstory` | `su shortstory -c /bin/true`（起 PTY 喂口令） | 错口令 ⇒ `su: Authentication failure` |
| `root` / 其它 | **白名单外，连 PAM 都不碰**（连试都不试，堵掉拿本门爆破 root 的路） | 自测断言覆盖 |

- 两账号口令都可用：`passwd -S longxia` ⇒ `P`；以 shortstory 身份 `passwd -S` ⇒ `P`（2026-10-08 设置）。
- 口令只经 **stdin / PTY** 传，绝不进 argv、绝不落日志（`state/proxy.log` 只有「用户名 + 成功/失败 + 来源 IP」）。
- 失败限速：**5 次 / 5 分钟 / IP**（内存态，重启归零）⇒ 超了回 `429`。
  ⚠ 本机 PAM 栈里**没有** `pam_faillock`（`/etc/pam.d/common-auth` 无 faillock 条目）⇒ 试错不会锁死 Linux 账户。

## 四、安全边界（必须知道的两条）

1. **这是身份门，不是权限边界**：web 里跑的一切仍然以服务账号 `longxia` 身份执行。
   用 `shortstory` 登录**不会**让 agent 变成 shortstory，也读不到/写不了 shortstory 的家目录。
   真要按账户分权限，得给 shortstory 另起一个 DSH 实例（换 uid 跑 + 另开一个端口 + 同一套门）。
2. **`tailnet` 档 = 网内免二次口令**（这正是甲方要的方案①）。谁进了这个 tailnet 谁就能开；
   要收口就切 `password`。

## 六、锁死时的退路（**重要，尤其切到 password 之后**）

`password` 档下如果登录页不收你的口令（比如口误、或某账号口令被改），GUI 是打不开的 —— 此时：

```bash
# 从 Windows 上用 Termius SSH 进本机：
cd /home/longxia/vpsdsh-shortstory-workspace-wrapper.d
bash bin/web.sh gate tailnet      # 2 秒内恢复网内直通
```

等价做法：删掉 `state/gate.conf`（缺省即 `tailnet`）。本条已写进 `~/.dsh/AGENTS.md`。

## 七、件与坑

| 件 | 作用 |
|---|---|
| `bin/web-gate.py` | 门本体（纯标准库；off/tailnet/password；自动补令牌；登录页；限速） |
| `bin/selftest-web-gate.py` | 25 条断言的自测（假 DSH 上游 + 桩口令 + 真错口令） |
| `bin/proxy-run.sh` | tmux 会话 `dsh-proxy` 的前台运行体，现在 exec `web-gate.py` |
| `bin/web.sh gate …` | 切档 / 看档（写 `state/gate.conf`，600） |
| `bin/ts-proxy.py` | 老纯转发器，保留作对照/回滚 |
| `state/gate.conf` | 当前档（`mode = off\|tailnet\|password`），**不进仓** |
| `state/gate-secret.txt` | 登录 cookie 的 HMAC 密钥（自动生成，600），**不进仓** |

两个真踩到的坑（自测抓出来的，写在这里免得重犯）：

1. **`_read_head` 一次读 4 KB**，首包里常**连带**装进 body 的开头 ⇒ 谁要读 body 都必须先接住这段
   （门的登录表单、自测的假上游各踩一次，表现为"傻等永远等不到的字节"）。转发路径不受影响：整段 buffer 原样转出。
2. **用户 patch 层按 id 整条替换 config**（见 `profile/cordis.patch.yml` 的 `connection` 条目）：
   只写 `cookieMaxAgeDays` 会冲掉 `trustedHosts`，手机侧 `/api` 信任栅栏失守。

## 八、没做 / 可扩展

- **真权限隔离**（shortstory 登录后以 shortstory 身份干活）没做，见 §四.1。
- 登录页没有验证码 / 2FA / 记住我不久前端；限速是内存态。
- 没做 HTTPS：要 `https://…ts.net` 得再挂一条 `tailscale serve`（既有 443 那条属于另一条线，别动）。
