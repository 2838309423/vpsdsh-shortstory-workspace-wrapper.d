- ⚠ **2026-10-12 凌晨回滚：`split` ⇒ `tailnet`**（2026-10-12T01:35Z 甲方报障后处置）。

## 二、四档语义

| 档 | 谁能进 | 观感 |
|---|---|---|
| `off` | 与老 ts-proxy 完全一致：只有拿到 `?token=<当前令牌>` 并换到 cookie 的设备能进 | 回滚档，令牌一换书签就 401 |
| `tailnet`（方案①） | Tailscale 网内**任何**登录设备，直开干净 URL 即进 | 门发现 DSH 回 401（没 cookie）就自动补一次 `/?token=<当前令牌>` 跳转 ⇒ **永久书签**，重启也不怕 |
| `password`（方案②） | Tailscale 网内 **且** 在登录页用 **longxia / shortstory 的真实 Linux 口令**通过 | 打开干净 URL 先出登录页；通过后发 365 天 HMAC 签名 cookie，之后同① |
| `split`（**当前生效**，①+②同时） | 按请求 `Host` 分流：**Tailscale 域名 ⇒ 令牌档①**；**IP（及一切陌生 Host）⇒ 口令档②** | 两个书签同时可用：域名那条免口令直进，IP 那条先出登录页 |

四种档都**只在 Tailscale 网卡上监听**，公网 IP 上零监听（`ss -ltn | grep 19387` 只有 `127.0.0.1` 与 `100.85.190.17`）。

### 2.1 `split` 的分流规则（`bin/web-gate.py` 的 `is_token_host()`）

| Host 形态 | 判成 | 理由 |
|---|---|---|
| `ser542085963120.tailcd1620.ts.net`（本机 MagicDNS 名） | **令牌档①** | 任何 `*.ts.net` 后缀都算 ⇒ 换了 tailnet / 改了机器名也不用改配置 |
| `gate.conf` 里 `token_host = …` 显式列出的名字（支持 `.x` / `*.x` 后缀写法） | **令牌档①** | 非 ts.net 的自定义名、或想把某个 IP 也划进令牌档时用它 |
| 一切 IP 字面量：`100.85.190.17`、IPv6 `[fd7a:115c:a1e0::8931:be12]` | **口令档②** | 甲方口径原文：IP 访问就要用户口令 |
| 陌生主机名、缺 Host 头 | **口令档②** | 失败安全方向：不认识就按最严的来 |

- 令牌档**不认门 cookie、不出登录页**：`/login` 直接 303 回 `/`；域名下 DSH 回 401 就自动补当前令牌（含**已死的旧令牌链接自愈**）。
- 口令档**先要门 cookie**：`/api` 无 cookie ⇒ 401；页面无 cookie ⇒ 303 `/login`。登录页底部已写明"用域名打开则免口令"。
- 两个入口的 **DSH 会话 cookie 互不通用**：DSH 把 cookie 绑在 authority 上（域名:19387 ≠ IP:19387，实测互换用 ⇒ 401）。
  所以域名那条走令牌档、IP 那条走口令档，各自独立，不会互相串味。


## 三、口令怎么校验（无 root 权限，用系统自己的 PAM）

本机 `longxia` 无 sudo 免密、读不到 `/etc/shadow`，`sshd` 也是 `PasswordAuthentication no`（不能用 SSH 试口令）。
实测可行的两条路（都走 setuid 程序 → PAM）：

| 账号 | 校验方式 | 实测 |
|---|---|---|
| `longxia` | `sudo -S -k -u root /bin/true`（sudo 校验的是**发起者 longxia** 的口令） | 错口令 ⇒ `1 incorrect password attempt`，EXIT=1 |
| `shortstory` | `su shortstory -c /bin/true`（起 PTY 喂口令） | 错口令 ⇒ `su: Authentication failure` |
| `root` / 其它 | **白名单外，连 PAM 都不碰**（连试都不试，堵掉拿本门爆破 root 的路） | 自测断言覆盖 |

- 两账号口令都可用：`passwd -S longxia` ⇒ `P`；以 shortstory 身份 `passwd -S` ⇒ `P`（2026-10-08 设置）。
- 口令只经 **stdin / PTY** 传，绝不进 argv、绝不落日志（`state/proxy.log` 只有「用户名 + 成功/失败 + 来源 IP」）。
- 失败限速：**5 次 / 5 分钟 / IP**（内存态，重启归零）⇒ 超了回 `429`。
  ⚠ 本机 PAM 栈里**没有** `pam_faillock`（`/etc/pam.d/common-auth` 无 faillock 条目）⇒ 试错不会锁死 Linux 账户。

## 四、安全边界（必须知道的两条）

1. **这是身份门，不是权限边界**：web 里跑的一切仍然以服务账号 `longxia` 身份执行。
   用 `shortstory` 登录**不会**让 agent 变成 shortstory，也读不到/写不了 shortstory 的家目录。
   真要按账户分权限，得给 shortstory 另起一个 DSH 实例（换 uid 跑 + 另开一个端口 + 同一套门）。
2. **`split` / `tailnet` 档 = 网内免二次口令**（这正是甲方要的方案①）。谁进了这个 tailnet 谁就能开；
   要全面收口就切 `password`（IP 那条已经在口令档上了）。
3. **域名档 ≠ 更强的身份**：`split` 只是"域名走①、IP 走②"的**分流**，域名本身没有额外的 Tailscale 身份层
   （门是裸 TCP 门面，不经 `tailscale serve` 的 whois 头）⇒ 域名免口令的信任来源仍是「设备已在 tailnet 里」。

## 六、锁死时的退路（**重要，尤其切到 password 之后**）

`password` 档下如果登录页不收你的口令（比如口误、或某账号口令被改），GUI 是打不开的 —— 此时：

```bash
# 从 Windows 上用 Termius SSH 进本机：
cd /home/longxia/vpsdsh-shortstory-workspace-wrapper.d
bash bin/web.sh gate split        # 回到 split（域名那条免口令，立刻能进）
bash bin/web.sh gate tailnet      # 或干脆网内直通（2 秒内生效）
```

**`split` 档下这个风险小得多**：即使 IP 入口的登录页不收口令，**域名入口 `http://ser542085963120.tailcd1620.ts.net:19387/`
走令牌档、不看口令**，照样能进 GUI ⇒ 不必非得 SSH 兜底。

等价做法：删掉 `state/gate.conf`（缺省即 `tailnet`）。本条已写进 `~/.dsh/AGENTS.md`。

## 七、件与坑

| 件 | 作用 |
|---|---|
| `bin/web-gate.py` | 门本体（纯标准库；off/tailnet/password/**split**；自动补令牌；登录页；限速；按 Host 分流） |
| `bin/selftest-web-gate.py` | 38 条断言的自测（假 DSH 上游 + 桩口令 + 真错口令 + split 分流） |
| `bin/proxy-run.sh` | tmux 会话 `dsh-proxy` 的前台运行体，现在 exec `web-gate.py` |
| `bin/web.sh gate …` | 切档 / 看档（写 `state/gate.conf`，600）；`split` 档会同时印出两个书签 |
| `bin/env.sh` | 统一环境；`DSH_WEB_DNS` = 本机 MagicDNS 名（令牌档书签 + `/api` 信任栅栏都用它） |
| `bin/ts-proxy.py` | 老纯转发器，保留作对照/回滚 |
| `state/gate.conf` | 当前档（`mode = off\|tailnet\|password\|split`，可加 `token_host = …`），**不进仓** |
| `state/gate-secret.txt` | 登录 cookie 的 HMAC 密钥（自动生成，600），**不进仓** |

两个真踩到的坑（自测抓出来的，写在这里免得重犯）：

1. **`_read_head` 一次读 4 KB**，首包里常**连带**装进 body 的开头 ⇒ 谁要读 body 都必须先接住这段
   （门的登录表单、自测的假上游各踩一次，表现为"傻等永远等不到的字节"）。转发路径不受影响：整段 buffer 原样转出。
2. **用户 patch 层按 id 整条替换 config**（见 `profile/cordis.patch.yml` 的 `connection` 条目）：
   只写 `cookieMaxAgeDays` 会冲掉 `trustedHosts`，手机侧 `/api` 信任栅栏失守。
3. **拿备用端口演练 split 时，curl 的 `Host:` 必须仍写真实端口 `:19387`**（2026-10-12 实测）：
   DSH 的 `/api` 信任栅栏比对的是 `authority` 整串，`Host: …ts.net:19488` 不在 `trustedHosts` 里 ⇒ **403**，
   会让人误以为分流写坏了。DSH 的会话 cookie 同样绑 authority ⇒ 在 19488 换来的 cookie 拿到 19387 用会 401。

## 八、没做 / 可扩展

- **真权限隔离**（shortstory 登录后以 shortstory 身份干活）没做，见 §四.1。
- 登录页没有验证码 / 2FA / 记住我不久前端；限速是内存态。
- 没做 HTTPS：要 `https://…ts.net` 得再挂一条 `tailscale serve`（既有 443 那条属于另一条线，别动）。
